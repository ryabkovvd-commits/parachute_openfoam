# Баланс импульса сохранённых расчётов проницаемого купола

Инструмент предназначен для фиксированных одношаговых случаев серии `run/permeability_models/8996`. Он проверяет нагрузку в стационарном несжимаемом расчёте `simpleFoam` с текущей моделью `kOmegaSST` и источником сопротивления строп `cordDrag`. Нового CFD-решения, изменения формы или подстановки нового закона ткани нет.

Цель — отделить ошибку переноса давления на структурные узлы от возможного несоответствия между учитываемой нагрузкой и переносом импульса через проницаемый интерфейс. Для серии 8996 перенос уже проверен: моменты давления отрицательны непосредственно по CFD-граням, а ошибка переноса составляет менее 0,075% полного момента.

## Величины и знаки

Нормаль каждой грани направлена наружу **из жидкой расчётной области**. Для внутренних перегородок это две противоположные нормали. В поле OpenFOAM `phi` хранится знаковый объёмный поток через грань. `p` — кинематическое давление, поэтому при интегрировании используется множитель `rho`.

На каждой грани вычисляются:

\[
\mathbf f_p=\rho p\mathbf S_f,\qquad
\mathbf f_\tau=-\rho\boldsymbol\tau_k\mathbf S_f,\qquad
\mathbf f_c=\rho\mathbf U_f\phi_f,
\]

где `tau_k = (nu+nut)*dev(grad(U)+grad(U).T)`. Это реконструкция девиаторного напряжения для текущей линейной модели турбулентной вязкости. Дополнительный изотропный член `k` к давлению не добавляется. Момент каждой составляющей — `(faceCentre-origin) × force`, начало координат совпадает с коушем, `(0,0,0)`; исследуемая компонента — `+Y`.

Интерфейс `Gamma` включает `canopy` и `canopy_slave`; внешняя граница `B` включает остальные патчи. Для стационарной постановки сопоставляются:

\[
\mathbf L_{\rm outer}=-\sum_B(\mathbf f_p+\mathbf f_\tau+\mathbf f_c),
\]

\[
\mathbf L_{\rm interface}=\sum_\Gamma(\mathbf f_p+\mathbf f_\tau+\mathbf f_c)
+\mathbf F_{\rm cords}.
\]

Аналогично вычисляются моменты. Разность второй и первой оценки записывается как невязка баланса. Конвективная составляющая интерфейса дополнительно разделяется на нормальную и касательную.

**Балансовая оценка реакции интерфейса не заменяет автоматически механическую нагрузку ткани.** Сначала требуется проверить замыкание баланса, реконструкцию напряжений, применённые силы строп и смысл граничного условия. Член `rho*Un*delta(Ut)` может отражать обмен импульсом, заложенный в условии вдува–отсоса; его наличие ещё не валидирует этот обмен для реальной ткани.

## Требуемые данные

- Общая форма и сетка должны проходить существующую проверку `permeability_models.verify`.
- Поля `U`, `p`, **`phi`**, `nut` при 2000 итерациях — из архива прохода либо из сохранившегося рабочего случая. Если доступны обе копии, их хеши должны совпадать.
- Полный `case/constant/polyMesh`, `constant/cords`, `constant/turbulenceProperties`, `system/fvSchemes`, `system/fvSolution`, `system/fvOptions`.
- Применённые силы строп из `postProcessing/cords/2000/*.dat`.

При отсутствии `phi` инструмент останавливается. Подстановка `U·Sf` вместо сохранённого потока давления не выполняется: именно их согласованность входит в проверку. Поддерживается восстановленная последовательная сетка с патчами типов `patch`/`wall`. Не поддерживаются процессорные куски, периодические патчи и нестационарные случаи с неучтённым изменением импульса во времени.

Если архив и рабочие поля отличаются, инструмент не смешивает их автоматически. Это ошибка происхождения данных, которую нужно разобрать до физической интерпретации.

## Как сохраняются исходные поля

`nos6MomentumAudit` читает поля как словари, сохраняя записанные значения границ. Исходный `codedFixedValue` **не создаётся и не исполняется**. Во временной копии поля используются с фиксированными сохранёнными значениями. Для `zeroGradient` без записанного `value` значение берётся из соответствующей ячейки-владельца. Другие условия без сохранённых значений отклоняются.

Исходные файлы и сетка копируются во временный каталог; функции из расчётного `controlDict` отключены. Вычисляется градиент сохранённого `U` с исходной схемой `fvSchemes`, но CFD-уравнения не решаются и модель турбулентности не корректируется. До и после проверки сравниваются SHA-256 исходных данных. Исходные АДХ, формы и `comparison.csv` остаются результатами первоначального расчёта.

## Стропы и дискретные поправки

Применённая сила берётся из сохранённого вывода источника, а не заново подбирается по итоговому `U`. Отдельно вычисляется сила по финальному полю скорости для оценки изменения внутри последней итерации.

Для глобального баланса момент источника считается в центрах ячеек, где приложена сила в `fvOptions`. Дополнительно сохраняется момент в точках стропы, используемых структурной моделью. Номер ячейки восстанавливается поиском на полной сетке. Для точек на гранях ячеек выбор может отличаться от исходного параллельного владельца; эта неопределённость отмечается в отчёте. Сильное различие применённых и пересчитанных сил требует проверки.

Выводятся интегральная невязка неразрывности и член `U*div(phi)`, который вычитается схемой `bounded` из конвекции. Последний является диагностикой дискретной схемы и не добавляется автоматически к нагрузке. Угловой момент в дискретной схеме и реконструированная вязкая тяга могут оставлять ненулевую невязку даже при малой невязке силы. Поэтому результат не маркируется автоматически как физически достоверный или сошедшийся.

## Запуск на кластере

После отдельного подтверждённого переноса обновления из GitHub, из корня `porousDisk_bundle`:

```bash
export NOS6_PYTHON=/home/016/apps/dashboard/anaconda3/bin/python
JBAL=$(sbatch --parsable cluster/momentum_balance.slurm run/permeability_models/8996)
JBAL=${JBAL%%;*}
printf 'Job: %s\n' "$JBAL"
squeue -j "$JBAL"
```

Задание запрашивает один процесс, два CPU и до двух часов. Память выделяется по настройкам раздела Slurm; явный запрос `--mem=8G` удалён после сообщения пользователя `Memory specification can not be satisfied`. Последовательно обрабатываются три случая; CFD не запускается. Скрипт загружает `openfoam/2212`, компилирует утилиту командой `wmake`, затем выполняет Python-постобработку. Другой модуль можно задать через `NOS6_OPENFOAM_MODULE`.

Для уже перенесённого файла убрать прежнюю директиву и повторить отправку можно без нового скачивания:

```bash
sed -i '/^#SBATCH --mem=8G$/d' cluster/momentum_balance.slurm
JBAL=$(sbatch --parsable cluster/momentum_balance.slurm run/permeability_models/8996)
JBAL=${JBAL%%;*}
printf 'Job: %s\n' "$JBAL"
```

В присваивании `JBAL=...` пробелов вокруг `=` нет. Отказ при отправке означает, что постобработка не запускалась; достаточность памяти по умолчанию оценивается отдельно после фактического запуска.

После завершения:

```bash
cat "momentum-balance-$JBAL.out"
cat run/permeability_models/8996/momentum_balance.csv
```

Для запуска вручную в уже выделенном вычислительном окружении:

```bash
module load openfoam/2212
wmake tools/momentumAudit
"$NOS6_PYTHON" coupled/momentum_balance.py run/permeability_models/8996 --binary "$FOAM_USER_APPBIN/nos6MomentumAudit"
```

## Результаты и порядок анализа

В каждом варианте создаётся `out/momentum_balance/`: `report.json`, `boundary.csv`, `volume.csv`, `cord_mapping.csv`, `native.log`. Общая таблица — `run/permeability_models/8996/momentum_balance.csv`. При ошибке одного случая другие обрабатываются, задание возвращает ненулевой код, а CSV содержит только успешно обработанные случаи. Старый CSV удаляется перед повторным запуском, чтобы не выдать прежний результат за новый.

1. Проверить расход: знаковые `Q_canopy` и `Q_slave` должны компенсироваться; посмотреть `Q_all`, локальную невязку неразрывности и отличие `phi` от `U·Sf`.
2. Сопоставить реконструированные давление и вязкий момент с сохранёнными `force.dat`/`moment.dat`. Различия записаны в `mz_pressure_minus_native`, `mz_viscous_minus_native`.
3. Оценить `mz_convection`, особенно касательную часть. Сравнить её масштаб с исходным отрицательным моментом.
4. Сопоставить `mz_interface_balance_with_cords` и независимый `mz_outer`; проверить остаток `mz_balance_residual`.
5. Если остаток велик, сначала разобрать стресс, неразрывность, силы источника и дискретизацию. Только при достаточном замыкании баланса обсуждать физическое значение обмена импульсом.

Полная постобработка серии 8996 на кластере ещё должна быть выполнена. Локальная компиляция и контрольные примеры относятся к OpenFOAM 2412; исполнение на 2212 подтверждается отдельно по журналу кластера. Использованные конструкторы чтения словарей и полей присутствуют в [API OpenFOAM 2212](https://api.openfoam.com/2212/classFoam_1_1IOdictionary.html).

# Автоматическая обработка расчётов купола

Обновление от 19.11.2026. Пользователь подтвердил запуск непроницаемого купола на кластере. Номер нового массива в чате пока не передан. Публикация исходников на GitHub и их перенос на кластер учитываются раздельно.

## Что показал аудит

Прежний `nos6_held.slurm` после каждого угла создавал единый STL купола со стропами и запускал `plots.py`. Последний строил историю коэффициентов, карту перепада давления, сечения давления и скорости, линии тока и изменение профиля при наличии соответствующих полей. Часть функций молча возвращалась при отсутствии данных. Нагрузка на общий узел, отдельные CSV, эпюры по меридианам и сводные АДХ требовали ручных команд. Проверки сохранения силы и момента при переносе не включались в общий отчёт.

Теперь сценарии `nos6_held.slurm` и `nos6_wall.slurm` вызывают единый `coupled/nos6_results.py case`. Он повторно использует `plots.py`, `pressure_table.py`, `cord_study.py`, `vtp.py` и существующий экспортёр геометрии. Новая физическая диагностика вынесена в `aero_diagnostics.py`. Расчётная модель и критерии остановки в этом обновлении не меняются.

Отсутствующие проходы отмечаются, а не выдаются за полную анимацию.

## Как обработать уже запущенный расчёт

Slurm сохраняет собственную копию отправленного сценария. Замена файла сценария в репозитории не переводит уже запущенный массив на новую последовательность постобработки. Поэтому для текущего непроницаемого расчёта новую обработку удобно поставить отдельным заданием после завершения массива.

Сначала перенесите обновлённые исходники из GitHub: каталоги `coupled/` и `cluster/`. Каталог `references/` нужен только при явном подключении предварительной оцифровки. Наличие файлов в GitHub не считается подтверждением их переноса пользователем.

В том же терминале, где переменная J содержит номер запущенного массива:

```bash
cd ~/porousDisk_bundle
export NOS6_PYTHON=/home/016/apps/dashboard/anaconda3/bin/python
printf 'Расчётный массив: %s\n' "$J"
sbatch --dependency=afterany:"$J" cluster/postprocess.slurm "run/nos6wall/$J"
```

Проверьте, что J действительно содержит нужный номер. `afterany` позволяет обработать также сохранённые результаты углов, не достигших сходимости. Их статус не меняется на «сошёлся». Сам обработчик не запускает новый CFD-расчёт или релаксацию формы. Для повторной трассировки линий `plots.py` использует OpenFOAM в режиме постобработки.

Если расчёт уже завершён, зависимость не требуется:

```bash
sbatch cluster/postprocess.slurm "run/nos6wall/$J"
```

Новый сценарий обработки запрашивает один узел, одну задачу и четыре процессора на задачу. Итоговые журналы находятся в `postprocess-<номер>.out`, подробности штатных рисунков — в `out/plots_postprocess.log` каждого угла. Ресурсы можно переопределить при `sbatch`.

Для GIF всех проходов перед отправкой задания:

```bash
export NOS6_GIF=all
sbatch --dependency=afterany:"$J" cluster/postprocess.slurm "run/nos6wall/$J"
```

При дальнейшем создании обычных расчётных заданий обновлённые Slurm-сценарии уже выполняют эту последовательность автоматически после каждого угла. Физическая модель стенки включается отсутствием `--fabric`, а не бесконечно большим коэффициентом сопротивления ткани.

## Одна команда для одной папки или нескольких серий

Для одного уже известного угла:

```bash
"$NOS6_PYTHON" coupled/nos6_results.py case run/nos6held/8881/a00 --speed=30
```

Для общей таблицы проницаемых и непроницаемых случаев:

```bash
"$NOS6_PYTHON" coupled/nos6_results.py polar pics/adh_compare run/nos6held run/nos6wall
```

Разные номера массивов остаются отдельными сериями, чтобы повторы с изменёнными параметрами не соединялись автоматически в одну кривую. CSV содержит путь, модель ткани, номер прохода, статус и все доступные поля истории. Кружок на графике означает подтверждённый файл сходимости именно для последнего прохода; крест — подтверждённую несходимость; треугольник — отсутствие достоверного статуса. Размах трёх последних проходов служит диагностикой итерационного дрейфа, а не доверительным интервалом или амплитудой физической пульсации.

Поиск ограничен структурой папок расчётов и не обходит все файлы `polyMesh` и `processor*`. Общая сводка массива защищена `flock` на Linux от одновременной записи двух углов. Если отдельный этап недоступен, остальные продолжаются; общий отчёт получает `partial` либо `failed` с причиной. Неудачный этап не скрывается наличием старой картинки.

## Если извлечение эпюр сообщает ambiguous inside/outside normals

Условие 99% проверяет знак скалярного произведения нормали CFD-грани на вектор от коуша к её центру. Это геометрическое предположение обработчика, а не критерий сходимости OpenFOAM. Противоположные знаки могут быть связаны с гранями разреза, локальной геометрией или ориентацией поверхности; один этот тест причины не различает. Порог нельзя автоматически ослаблять для получения желаемой эпюры.

Для диагностики без определения внутренней/наружной стороны:

```bash
"$NOS6_PYTHON" coupled/pressure_table.py run/nos6held/8883/a30 --V=30 --diagnose-normals --pics=run/pressure_compare_a30
```

Команда выводит по одной короткой строке для master и slave; сохраняет JSON со статистикой по площади, CSV с координатами всех граней и их радиальным знаком, а также PNG с расположением меньшинства граней противоположного знака. Ни давление, ни нормали расчёта не исправляются. Эта команда не является разрешением неоднозначности. Подтверждение складки или ошибки ориентации требует просмотра геометрии и соответствия граней.

При обработке нескольких случаев ошибка одного из них больше не препятствует построению рисунков успешно обработанных случаев. Код завершения остаётся ненулевым, а в сообщении явно указана неполная обработка. На рисунках и в легенде профилей присутствует идентификатор случая, поэтому одинаковый угол разных серий не делает их неразличимыми.

## Расстояния выборки давления в каждой точке профиля

Режим `--sampling-report` выводит таблицу с префиксом `sample`. Все расстояния в ней заданы в метрах:

```bash
"$NOS6_PYTHON" coupled/pressure_table.py run/nos6wall/8928/a40 --V 30 --sampling-report --pics run/pressure_distances | grep '^sample'
```

Столбцы: R, R_left, R_right, near_in_m, near_out_m, raw_out_m, support_out_m. Компактная эпюра интерполируется между полными отсчётами R_left и R_right. Для неё выводится максимум соответствующего расстояния в этих двух отсчётах: это не фиктивная новая CFD-грань в точке компактной таблицы. near означает ближайшую допустимую грань после фильтров; raw_out — ближайшую наружную грань без фильтров сектора и нормали; support_out — расстояние до самой дальней реально использованной соседней грани. Две дополнительные строки sample_max показывают точную полную координату R максимального расстояния отдельно для каждой стороны, включая её нефильтрованное расстояние и охват соседей. Малое расстояние само по себе не доказывает корректность давления.

Вместе с эпюрами сохраняются `_sampling_full.csv` и `_sampling_compact.csv`. Полная таблица содержит координаты точек запроса, номера ближайших допустимых и нефильтрованных граней обеих сторон, расстояния и соответствие нормалей. Эти файлы также включены в единую автоматическую обработку `nos6_results.py`. Алгоритм расчёта давления, фильтры и веса не изменены.

## Выборка возле закрытого полюса

На 8928/a40 выявлено: при R=+0.00641 ближайшая допустимая грань находилась на 0.19040 м, хотя нефильтрованная — на 0.02132 м. Обе локальные нормали согласованы с нормалью профиля (косинусы около 0.99855 и 0.99994). Точка запроса расположена примерно в 2.93 мм от оси через коуш, так что сектор ±6° здесь имеет полуширину всего около 0.31 мм. Жёсткое ограничение азимута становится недостаточным способом локальной интерполяции в этой области.

Теперь в центральном веере закрытого полюса (|R|≤1/(rings+1) для стандартной геометрии) выбираются ближайшие в пространстве грани с прежними фильтрами радиальной ориентации и локальной нормали. Усреднение по всему кольцу не выполняется. За пределами веера угловой сектор сохранён. Для открытого полюса эта поправка не применяется. Размер освобождённой области записан в metadata.json как closed_pole_sector_exemption_R. Режим --strict-pole-sector воспроизводит прежнее ограничение сектора во всех ненулевых точках для проверки чувствительности.

Исправление относится только к постобработке эпюр. Расчёт CFD, перенос нагрузок и ранее рассчитанные АДХ не меняются. Работу на конкретной кластерной сетке проверяют повторным --sampling-report; до получения этого вывода нельзя объявлять расстояние 19 см устранённым в реальном случае.

## Контрольная локальная выборка вдоль всего профиля

После поправки веера на 8928/a40 максимум сместился на R=+0.08333, первый отсчёт за его границей: near=0.08877 м, raw=0.02045 м, support=0.11418 м. Поправка веера была частичной; её границу не следует расширять вручную для получения нужного результата.

Для отдельного контролируемого сравнения добавлен --local-sampling:

```bash
"$NOS6_PYTHON" coupled/pressure_table.py run/nos6wall/8928/a40 --V 30 --neighbours 4 --local-sampling --sampling-report --pics run/pressure_local | grep '^sample_max'
```

Меридиан задаётся координатами точек запроса на входной CFD-форме. В этом режиме из каждого патча выбираются N ближайших в пространстве граней, прошедших прежние проверки стороны и локальной нормали. Веса остаются обратно пропорциональными расстоянию; осреднения всех граней кольца нет. Угловой сектор не используется. Это дополнительный режим, не автоматическая смена методики существующих обработок. Выбранный метод записывается как sampling_method=local_3d_neighbours; без флага сохраняется angular_sector с ранее описанной поправкой веера. Одновременный --strict-pole-sector запрещён.

Новый режим нужно проверить по расстояниям, изменению эпюр и их чувствительности к N. Он не устраняет возможную ошибку самой CFD-сетки или давления и не обходит отказ неоднозначного определения сторон проницаемого купола. Поля CFD и интегральные АДХ не пересчитываются.

## Научный смысл новых диагностик

В статье Апаринова, Зайчука и Пономарева 2003 года фиг. 6 сопоставляет эпюры перепада и профили при разных углах. Эта логика используется в паре наших рисунков давления и формы. Она позволяет выяснить, какая часть купола разгружается, хотя интегральный Cx может оставаться близким. [Первоисточник](https://mtt.ipmnet.ru/files/2003/2003-3/mtt2003_n3_p155-172.pdf).

Zhang и соавторы в работе 2024 года анализируют деформации, коэффициенты сил и вихревую структуру, а для передачи данных между расчётами вводят явное соответствие сеток. Для нашей задачи полезны совместный анализ формы и потока и отдельная проверка переноса нагрузок. Их расчёт описывает нестационарное наполнение; наши внешние проходы не являются его временными шагами. Поэтому спектры «дыхания», физические частоты и ударный пик наполнения из нынешней истории проходов не вычисляются. [Первоисточник, §§3 и 6](https://link.springer.com/article/10.1186/s42774-023-00162-0).

При диагностике давления вычисляются две суммы. Первая воспроизводит текущую схему чтения и переноса, включая ближайшие соответствия всех граней. Она нужна для проверки истории расчёта. Вторая включает только взаимно согласованные пары с расстоянием не более 10⁻⁴ м; ею окрашен VTP и построены вклады участков. В JSON явно указана покрытая площадь. При неполном покрытии эту сумму нельзя выдавать за полную аэродинамическую нагрузку. Давление не включает вязкую касательную тягу; вклад сопротивления строп вычитается из итоговых коэффициентов при сверке давления с историей.

Момент считается относительно коуша по компоненте +Y OpenFOAM, обозначаемой в нашей истории mz. Силы сопротивления и поперечная сила направлены соответственно по +Z и +X. Нормировка момента — qS₀D₀. Поперечные полосы рисунка вклада момента задаются геометрической координатой x′/R кромки относительно среднего центра кромки. Она отличается от материальной координаты R по раскрою на меридиональных эпюрах Носарева. Плечо для момента при этом всегда отсчитывается от коуша.

В сечении рассчитывается только ωy = ∂Ux/∂z − ∂Uz/∂x, нормированная на V/D₀. Производные берутся на треугольниках исходного сохранённого сечения. Это не модуль трёхмерной завихренности и не λ₂. Оранжевым выделяется Uz<0 при основном потоке +Z. Доля точек обратного течения в JSON не является долей объёма. Цветовая шкала ωy ограничена 98-м процентилем для читаемости, а CSV сохраняет весь диапазон.

## Давление Носарева

Файл `references/nosarev1976_pressure_preliminary.csv` содержит ранее выполненную ручную оцифровку фиг. 19а, 20 и 21 при 0°, −15° и −40°. Условия относятся к проницаемому куполу W=600 л/(м²·с). Это не эксперимент непроницаемого купола на фиг. 32. Точки не включаются автоматически в рисунки стенки.

Явное наложение на эпюры подходящего проницаемого случая:

```bash
"$NOS6_PYTHON" coupled/nos6_results.py case run/nos6held/8881/a00 --speed=30 \
    --reference=references/nosarev1976_pressure_preliminary.csv
```

Интервалы ±0,05 отражают принятую точность чтения скана, а не экспериментальную неопределённость. Cp внутри, Cp снаружи и перепад считывались независимо, поэтому отдельные округлённые строки могут не замыкаться точно по разности. Перед количественной оценкой ошибки требуется повторная сверка первоисточника. По рис. 32 не создаётся искусственная точная таблица из ориентировочных значений, прочитанных на глаз.

## Что стоит проверить следующим этапом

1. Выполнить согласованную сеточную проверку минимум на трёх сетках для стенки и ткани, сохраняя форму и параметры. Соседние проходы FSI не заменяют сеточную сходимость.
2. Сопоставить истинные трёхмерные структуры Q или λ₂ по полным согласованным полям, если нужны вихревые изоповерхности как в работах FSI. Двумерного сечения для них недостаточно.
3. Проверить зависимость эпюр от выбора меридиана через стропу и между стропами, ширины сектора и числа соседних граней.
4. Для нагрузки во времени, частот пульсации и физического наполнения нужен нестационарный расчёт с единым временем.
5. Для напряжений ткани в Па требуется согласованная мембранная модель и материальные параметры. Усилия эквивалентных стержней нельзя автоматически назвать полем напряжений ткани.

## Проверка реализации

Тесты запускаются стандартным `unittest` без отдельной зависимости pytest:

```bash
"$NOS6_PYTHON" -m unittest discover -s tests -v
```

Дополнительно до исполнения CFD компилируются обе конфигурации драйвера — стенка и проницаемая ткань — с проверкой неизменности критериев и подключения строп. Проверяются нормировка давления и опорного давления, выбор времени и прохода, перестановка имён патчей, отсев несовместимых нормалей, явная ошибка при отсутствии входной формы, сохранение результирующей силы, аналитический градиент завихренности, устаревший статус сходимости и продолжение этапов после локальной ошибки. Синтетические данные служат проверкой алгоритмов, а не валидацией парашюта.

Отдельно выполнена обработка реального исторического архива `n24_a25`, D₀=19,51 м, V=9 м/с, проход 2. Восстановлены Cx=0,6263345246, Cy=0,3324890510 и mz=0,0334163767, совпадающие с JSON. Относительная невязка результирующей силы между гранями и узлами — около 1,5·10⁻¹⁵, абсолютное различие коэффициента момента — около 4,70·10⁻⁵. Рисунки в примерах относятся к этому архиву, а не к запущенной сейчас серии 6 м². Отсутствующая в старом архиве невязка нагрузки отмечается явно.

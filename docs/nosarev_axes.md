# Расчёт в скоростной системе Носарева

## Назначение

Новый профиль `nosarev_axes` задаёт глобальные координаты OpenFOAM по
скоростной системе на фиг. 2 Носарева. Ось **+x направлена по скорости
снижения**, относительный набегающий поток — **−x**. Положительная ось y
соответствует поперечной оси этой правой системы, момент тангажа определяется
относительно **+z**. Начало координат остаётся в общем узле строп — коуше.
Используется скоростная система, а не обозначенная на том же рисунке связанная
система x₁, y₁, z₁. Источник определения: Носарев, фиг. 2 и пояснения к осям;
локальная копия проекта: `07.JPG`, определения коэффициентов: `08.JPG`.

Это отдельный расчётный профиль на общей кодовой базе. Форма, STL, сетка,
начальные поля, точки приложения нагрузок и архивы действительно записываются
в новых координатах. Для повторного использования механического ядра его
вычисления выполняются во внутренней рабочей системе, а входные и выходные
векторы согласованно преобразуются. Нового закона ткани или нового решателя
этот профиль не вводит.

## Соответствие координат и коэффициентов

Правый поворот из прежних глобальных координат имеет вид:

```text
x = −Z_old
y = −X_old
z = +Y_old
U = (−V, 0, 0)
```

Матрица ортогональна, её определитель равен +1. Поэтому силы и моменты
преобразуются одной матрицей. Момент вычисляется непосредственно как
`sum((r − r_coosh) × F)`, затем берётся его **z-компонента**:

```text
q  = rho * V**2 / 2
S0 = pi * D0**2 / 4
Cx = −Fx / (q*S0)
Cy =  Fy / (q*S0)
mz =  Mz / (q*S0*D0)
Mz = sum(rx*Fy − ry*Fx)
```

При чистом преобразовании одного физического состояния **Cx сохраняется,
Cy меняет знак относительно старого вывода, mz сохраняется**. Ранее для mz
использовался My; теперь +Y_old совпадает с +z. Поворот координат сам по себе
не устраняет расхождение момента с экспериментом.

В нашей модели положительный угол задаётся отклонением средней оси купола
от −x к −y. Для идеальной оси её направление равно
`(−cos(alpha), −sin(alpha), 0)`. Положительный Mz увеличивает этот угол.
На фиг. 2 источника изображён отрицательный угол; схема для +30° будет
отклонена в противоположную сторону при тех же направлениях осей.

## Состав кода

| Файл | Назначение |
| --- | --- |
| `coupled/nosarev_axes.py` | Профиль для `cs.py`, отметка системы в результатах и настройках. |
| `coupled/nosarev_frame.py` | Поворот геометрии и словарей, согласование структурного ядра и нагрузок. |
| `coupled/nosarev_project.py` | Подготовка контрольного случая на общей сетке, сравнение и схема координат. |
| `coupled/nosarev_view.py` | Временный вид данных для существующих алгоритмов рисунков; пересчёт точек трассировки обратно в глобальную систему. |
| `coupled/nosarev_plots.py` | Запуск штатных рисунков и GIF для новых координат. |
| `cluster/nosarev_axes.slurm` | Отдельный запуск на 72 процессах MPI одного узла, до двух суток. |

Обновлены `nos6_results.py`, `aero_diagnostics.py`, `pressure_table.py` и
`plots.py`: выбор осей, составляющие момента, размеры формы, обработка
следа и защита от ошибочного использования старой системы. В
`fixed_mesh_check.slurm` добавлена явная отметка координат внешней сетки.
Базовые `coupled.py`, `cs.py`, механическое ядро, закон ткани и сопротивление
строп остаются общими.

## Подготовка на кластере

Перенесите обновлённые папки `coupled` и `cluster` из репозитория с заменой
программных файлов. Существующую папку `run` сохраняйте. Перенос этой версии
нужно подтвердить отдельно: публикация на GitHub не означает установку на
кластере.

Из корня `porousDisk_bundle`:

```bash
export NOS6_PYTHON=/home/016/apps/dashboard/anaconda3/bin/python
"$NOS6_PYTHON" -m compileall -q coupled
bash -n cluster/nosarev_axes.slurm
```

Для контрольного сравнения используйте уже проверенный случай 9014:
его точная входная CFD-форма и согласованная сетка копируются в новый
каталог и поворачиваются `transformPoints`. Старые поля скорости и давления
не переносятся; начальные поля создаются заново.

```bash
export NOS6_CFD_ITERS=200
sbatch cluster/nosarev_axes.slurm 30 run/fixed_mesh_check/9014
```

Результат появится в `run/nosarev_axes/НОМЕР_ЗАДАЧИ/inner/a30`.
Этот запуск проверяет эквивалентность координат на фиксированной форме;
один CFD-проход не означает сходимость связанной задачи. Сравнивать надо с
тем же количеством итераций источника: файл `coordinate_comparison.json`
отдельно сообщает, одинаково ли это количество.

После завершения подставьте фактический номер задачи:

```bash
W=run/nosarev_axes/НОМЕР_ЗАДАЧИ/inner/a30
cat "$W/out/coordinate_comparison.json"
grep 'internalField' "$W/case/0/U"
```

Должно быть `internalField uniform (-30.000000 0.000000 0.000000);`.
Возможна запись отрицательного нуля: это численно то же значение.
В сравнении проверяются Cx_new≈Cx_old, Cy_new≈−Cy_old, mz_new≈mz_old.
Небольшие различия возможны из-за разбиения MPI, округления и конечного
числа итераций; существенное отличие требует проверки, а не изменения знака
момента вручную.

## Полный связанный расчёт

После контрольного теста запускается расчёт с формообразованием:

```bash
export NOS6_CFD_ITERS=2000
sbatch cluster/nosarev_axes.slurm 30
```

По умолчанию: купол площадью раскроя 6 м², закрытый свободный полюс,
96 узлов по окружности, 12 колец, 24 стропы длиной D₀, V=30 м/с,
ν=1.46e−5 м²/с, проницаемость `--fabric=33.2,28.6`, сопротивление строп
диаметром 3.2 мм при Cd=1.2. Используется `grad(p) Gauss linear`,
сгущение сетки 1.25, удержание средней оси внутри структурной релаксации
`inner`, от 6 до 12 проходов. Критерии остановки сохранены: невязка формы
менее 0.03 D₀, |ΔCx|<0.003 и завершённая релаксация два прохода подряд.
Невязка нагрузки остаётся диагностикой.

Параметры меняются перед отправкой задачи:

```bash
export NOS6_MESH=1.25
export NOS6_ATTITUDE=inner
sbatch cluster/nosarev_axes.slurm 35
```

Новая система не исправляет потерю парных граней при очистке сетки.
Защита `Unpaired fabric face` сохраняется: такую сетку нельзя принимать
как корректный проницаемый интерфейс.

## Рисунки, модели и повторная обработка

После CFD автоматически запускаются общая обработка результатов и схема
координат. Сохраняются таблицы АДХ, графики сходимости, давление, скорость,
линии тока, форма и STL. `coordinate_scheme.png` показывает оси, поток и
положительное направление момента на точной геометрии последнего CFD-прохода.
Ошибки обработки возвращаются в код завершения задания; подробности находятся
в `out/postprocess_report.json`.

Меридиональные эпюры строятся только при выполнении проверки ориентации
поверхности. На локальной грубой сетке контрольного теста согласованы 97.5%
ориентированных площадей при требуемых 99%: эпюра заблокирована в обеих
системах, а карта перепада на парных CFD-гранях построена. Порог не ослаблялся.
В фиксированном случае нагрузка коуша по старым структурным натяжениям
не считается откликом на новый поток, поэтому этот этап обработки пропускается.

Повторная обработка и GIF:

```bash
"$NOS6_PYTHON" coupled/nos6_results.py case "$W" --speed=30 --wake=1 --gif=off --no-summary
"$NOS6_PYTHON" coupled/nosarev_project.py diagram "$W"
"$NOS6_PYTHON" coupled/nosarev_plots.py nos6_held --run="$W" --V=30 --wake=1 --gif=all
```

Для выполнения этих команд в отдельной вычислительной задаче используйте
имеющийся механизм `cluster/postprocess.slurm`. Прямой запуск `plots.py`
для нового профиля намеренно запрещён, чтобы оси не были подписаны ошибочно.
Линии тока используют прежний алгоритм; точки, отправляемые решателю,
поворачиваются в фактическую глобальную систему.

STL `pics/parachute.stl` — последняя форма после релаксации, а
`pics/parachute_last_cfd.stl` — форма, на которой вычислено последнее давление.
Они могут немного различаться. Для эпюр и момента всегда используется
точная входная CFD-форма. Профили по меридиану остаются в явно обозначенной
локальной системе купола; их координату R нельзя без проверки отождествлять
с экспериментальной координатой источника.

## Ограничения сравнения

Локальная проверка выполнена в OpenFOAM 2412: одна фиксированная форма,
одна сетка из 18 465 ячеек, четыре процесса MPI и 200 итераций SIMPLE.
Профиль ткани, сопротивление строп, начальные поля турбулентности и схемы
одинаковы. Получены:

| Система | Cx | Cy | mz |
| --- | ---: | ---: | ---: |
| Прежняя | 0.52885601 | +0.21079033 | −0.07626402 |
| Скоростная Носарева | 0.52891728 | −0.21079484 | −0.07629020 |

Отклонения от преобразования составили 6.13e−5 для Cx, 4.50e−6 для Cy
и 2.62e−5 для mz. Разность осевых моментов, полученных непосредственно
функцией `forces` OpenFOAM, — около 0.238 Н·м при модуле 654 Н·м.
Проверка подтверждает согласованность реализации на этом локальном случае.
Она не заменяет проверку OpenFOAM 2212 на кластерной сетке случая 9014.
В локальной копии проекта исходные данные и журналы сохранены в
`reports/coordinates_nosarev_20261124/native_cfd`.
Краткий численный протокол: [nosarev_axes_local_check.json](../references/nosarev_axes_local_check.json).

Новый профиль обеспечивает согласованность координат. Он сохраняет наши
допущения о ткани, стропах и стационарном последовательном FSI. Удержание
средней оси не воспроизводит буквально стенд со скользящим полюсом.
Номера проходов не являются физическим временем наполнения. Совпадение после
поворота подтверждает реализацию, а не экспериментальную достоверность.
Следующий этап — сопоставить контрольный случай в новых осях, затем исследовать
влияние физической модели проницаемого интерфейса и формы на момент.

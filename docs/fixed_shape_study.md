# Полная серия: 21 состояние непроницаемого купола на фиксированной форме

## Запуск после одного переноса кода

Из корня кластерного проекта:

```bash
export NOS6_PYTHON=/home/016/apps/dashboard/anaconda3/bin/python
export NOS6_CFD_ITERS=2000
bash cluster/submit_fixed_shape_study.sh run/nos6wall/8928
```

Команда проверит архивы всех 11 углов, подготовит 21 геометрию, поставит
массив CFD и сбор результатов с зависимостью afterany. Номера заданий
сохраняются в setup/submission.json. Сбор выполняется после завершения
всех элементов массива, включая неуспешные. Старые случаи не перезаписываются.

По умолчанию используются 2000 SIMPLE-итераций, множитель сетки 1.25 и две
одновременные задачи. Настройки: NOS6_CFD_ITERS, NOS6_MESH, NOS6_MAX_PARALLEL,
NOS6_OPENFOAM_MODULE. Один элемент массива запрашивает узел и 72 MPI-процесса.
Требуются имеющиеся NumPy/Matplotlib, OpenFOAM и Slurm; новые API не нужны.

## Продолжение серии 9016 с 200 до 2000 итераций

После переноса новых файлов `cluster/extend_fixed_shape_study.py`,
`cluster/extend_fixed_shape_study.slurm` и `cluster/submit_extend_fixed_shape_study.sh`
из корня проекта на кластере:

```bash
export NOS6_PYTHON=/home/016/apps/dashboard/anaconda3/bin/python
bash cluster/submit_extend_fixed_shape_study.sh run/fixed_shape_study/9016
```

Продолжение охватывает все 21 состояние до общей отметки 2000 (ещё 1800
итераций для случая, завершённого на 200). Сохранённые сетки и поля используются
через `startFrom latestTime`; нового формообразования и построения сетки нет.
Если исходный массив ещё активен, продолжение ждёт его завершения через afterany.
Для проверки родительского номера массива используется `%F` команды squeue
([документация Slurm](https://slurm.schedmd.com/squeue.html)).
Параллельно запускаются не более двух случаев, по 72 MPI-процесса на каждый.
Отсутствующий каталог состояния рассчитывается с начала по той же подготовленной
геометрии. Частично повреждённый существующий случай не перезаписывается: ошибка
попадает в протокол и неполную сводку.

Исходный манифест и исходники `coupled/` не меняются, поэтому отпечаток кода
существующих случаев сохраняется. Новый setup содержит исходные хеши геометрии,
предел 2000, ссылку на прежний манифест и хеш инструмента продолжения. Малые
исходные метаданные, журнал и настройки сохраняются в `resume_2000_backup`
каждого случая; старые поля остаются на месте. `foamDictionary` в оболочке входа
не требуется: параметры изменяет Python, а OpenFOAM загружается в Slurm-задании.

После продолжения архивируются поля и давление на 2000, объединяются истории
нагрузок из папок `forces/0` и `forces/<итерация перезапуска>`, обновляются
коэффициенты по прежнему переносу давления на узлы и нагрузкам строп. Затем
перестраиваются графики случая и общая сводка с зависимостью afterany. Прежние
коэффициенты на 200 не подменяют новые результаты: сборка ожидает новый манифест
с пределом 2000 и явно показывает отсутствующие/неуспешные состояния.
Состояние продолжения записывается в `extension_2000.json`; достижение 2000
не меняет `CFD_convergence=unconfirmed` без анализа установления нагрузок.

Если исходная серия расположена иначе, замените run/nos6wall/8928 фактическим
путём. Нужны a00, a05, ..., a50 с историями и сохранёнными входными формами CFD.
Все исходники проверяются до отправки массива. Одной таблицы АДХ недостаточно.


## Задача и принятый статус исходных расчётов

По уточнению пользователя серия 8928 принимается сошедшейся по действовавшим
ограничениям. Новое исследование отделяет изменение геометрии при наклонном
обтекании от изменений численных схем. Оно не переименовывает исходные результаты
и не требует повторного формообразования всей серии.

При каждом угле сравниваются:

- `reference`: форма, которую CFD видел на последнем завершённом проходе при 0°,
  повёрнутая как твёрдое тело на заданный угол;
- `angle_shape`: форма, которую CFD видел на последнем завершённом проходе
  исходного расчёта при этом угле.

Обе формы заново рассчитываются как **непроницаемые** при общих настройках CFD.
Структурной релаксации нет. Разность `angle_shape - reference` оценивает влияние
геометрии при этих общих настройках. Старые коэффициенты 8928 сохраняются как
история происхождения; напрямую вычитать их из нового расчёта для выделения
деформации нельзя, поскольку численная схема могла измениться.

## Объём

Основная серия: 0–50° через 5°, 21 состояние и 11 сравнений по углам.
При 0° обе геометрии совпадают, поэтому выполняется один общий контроль.
Небольшой режим --pilot (семь состояний) оставлен только как явная опция. На случай запрашивается один узел, 72 MPI-процесса; одновременно
не более двух задач. Это параметры существующей очереди compute1, не оценка
доступности ресурсов или времени ожидания.

Общие настройки: S0=6 м², V=30 м/с, nu=1.46e-5 м²/с, rho=1.225 кг/м³,
24 стропы длиной D0, диаметр строп 3.2 мм, Cd=1.2, grad(p) Gauss linear,
длина турбулентности 1.24 м, интенсивность 1%, множитель сетки 1.25,
2000 SIMPLE-итераций и один внешний проход. 2000 итераций — заданный объём
нового расчёта, а не автоматическое доказательство установления CFD.

Сетки для разных геометрий строятся отдельно одинаковым алгоритмом и с
одинаковыми настройками. Их нельзя называть одной и той же сеткой.
Число ячеек может различаться; отдельная сеточная проверка в эти 21 состояние
не входит.

## Происхождение и контроль геометрии

Подготовка выбирает точный `fields/nos6_held/passNN/input_shape.npy` либо
сохранённый выход предыдущего прохода. Последний выход структурной релаксации
не подменяет форму, на которой рассчитаны соответствующие АДХ.
Проверяются масштаб, число узлов/колец/строп, длина строп, конечность координат
и положение коуша. Для старых записей без canopy_model явно сохраняется,
что принадлежность непроницаемой серии задана происхождением каталога.

Все формы приводятся в прежние глобальные оси. Если источник записан в
nosarev_speed, используется обратный собственный поворот. Затем средняя ось
ориентируется на требуемый угол единственным жёстким поворотом вокруг коуша:
расстояния между узлами не меняются. Новая механическая задача не решается.
Сохраняются SHA-256 источника, истории и подготовленной формы.

После расчёта проверяется точное сохранение подготовленных координат в CFD
и выходном файле, непроницаемое условие, физические параметры и grad(p).
Сборка сравнивает хеши fvSchemes, fvSolution и свойств среды для всех случаев.
При несовпадении настройки или изменении геометрии результат не принимается
как контролируемая пара. Натяжения исходной формы не выдаются за новый
структурный отклик при другой нагрузке.

## Раздельные команды и повторная сборка

Основной способ выше автоматически ставит CFD и сборку. При необходимости
можно подготовить и запустить задачи раздельно:

```bash
P=${NOS6_PYTHON:-python3}
"$P" coupled/fixed_shape_study.py prepare run/nos6wall/8928 run/fixed_shape_study/setup8928_full
J=$(sbatch --parsable cluster/fixed_shape_study.slurm run/fixed_shape_study/setup8928_full/manifest.json)
J=${J%%;*}
```

Полная серия включена по умолчанию в prepare и Slurm: массив 0-20%2.
Для prepare --pilot нужно явно передать sbatch --array=0-6%2.
Раздельный запуск ставит только CFD. Повторная ручная сборка:

```bash
"$P" coupled/fixed_shape_study.py collect "run/fixed_shape_study/$J" \
    --manifest run/fixed_shape_study/setup8928_full/manifest.json
```

В run/fixed_shape_study/НОМЕР автоматически создаются:

- geometry_comparison.json — все принятые состояния, разности, пропуски, ошибки;
- fixed_shape_cases.csv и geometry_effect.csv — коэффициенты и их разности;
- fixed_shape_polar.png/svg и geometry_effect.png/svg — полярные кривые и эффект формы;
- figure_provenance.json — источник и преобразования графиков;
- summary.md — полнота серии и описание результатов.

Пропуски показаны разрывами, а не нулями. При неполной серии отчёт сохраняется,
но сборка возвращает ошибку. complete=true означает наличие и согласованность
21 состояния, а не независимую валидацию или автоматическое установление CFD.
Производные таблицы и рисунки обновляются при явном повторном collect.

Манифест сохраняет отпечаток расчётного кода. При изменении кода после
подготовки задача откажется запускаться: нужно восстановить записанную версию
или создать новый setup. Переносить обновления в середине серии не следует.

## Сравнение двух способов удержания угла

Нужны итоговые парные каталоги legacy и inner с историей и сохранёнными
CFD-формами. В локальных отчётах на момент подготовки нет итоговой численной
пары, пригодной для такого сравнения; user-statement о сходимости принят,
но численные значения из него не восстанавливаются.

```bash
"$P" coupled/fixed_shape_study.py compare-holding \
    ПУТЬ_LEGACY/a30 ПУТЬ_INNER/a30 holding_a30_comparison.json
```

Команда сравнит итоговые Cx, Cy, mz, абсолютные и относительные изменения,
среднеквадратичное и максимальное различие входных CFD-форм. Системы координат
приводятся к одним осям. Физические параметры должны совпадать; фиксированный
CFD-тест не принимается за проверку метода структурного удержания.
При наличии отпечатков исходников и флагов отдельно отмечается, подтверждено
ли совпадение кода и всех настроек, кроме attitude. Без этого различие
результатов остаётся описательным и не приписывается одному удержанию.

Сравнение формы в этой команде включает всю сборку, включая стропные узлы.
Нулевой относительный знаменатель даёт null, а не бесконечный процент.

## Проверки подготовки

Тесты проверяют полную матрицу из 21 состояния и 11 сравнений, неполную серию,
повреждённые файлы, подачу Slurm со сборкой после afterany, а также: состав серии, сохранение расстояний при повороте,
источник входной CFD-формы, запрет подмены проницаемой геометрией, защита
подготовленных координат, нормировка осей, проверки готового результата,
и генерация настоящего драйвера без структурной релаксации.
Фикстуры тестов синтетические; это не новые научные результаты CFD.

## Инструменты подготовки графиков

Применены инструкции Scientific Agent Skills: Timothy Kassis, Vinayak Agarwal,
Yuhuan He, Darshil Patel, Aubrey M. Brueckner (2026), *Scientific Agent Skills:
A Library of Procedural Knowledge for Research Agents*,
[arXiv:2609.00065](https://doi.org/10.48550/arXiv.2609.00065).
Это ссылка на инструменты подготовки, а не источник результатов CFD.

Состояния запуска каждого случая записываются в study_run_status.json.
Ошибка отдельного графика после успешного CFD отражается в postprocess_returncode
и не подменяет статус численного решения.

Поддержан старый формат истории 8928 без отдельного D0: диаметр берётся из
объявленной площади 6 м² только после проверки номинальной длины строп D0
и дискретизации 96×12 с 24 стропами. Основание сохраняется в inferred_parameters.
Архив другого масштаба без D0 отвергается.

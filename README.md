# Круглый парашют 6 м² в OpenFOAM

Для остановок Unpaired fabric face в серии method_check/9008 подготовлена
[диагностика сетки до и после очистки](docs/mesh_probe.md).
Нужен один новый файл cluster/mesh_probe.slurm: он проверяет обе сохранённые
формы на исходной и сгущённой сетке без запуска CFD и без изменения старых
результатов. Сгущение пока является проверяемой гипотезой.

Подготовлены [исправления методики и парная проверка удержания угла](docs/method_fixes.md):
проверки параметров, геометрии, парности ткани, архивов и продолжения;
согласованные натяжения и нагрузка общего узла; экспериментальный режим
ограничения средней оси внутри структурной релаксации. Прежний режим удержания
сохранён по умолчанию. Для сравнения добавлен cluster/method_check.slurm.
Полный расчёт этой пары на кластере ещё не выполнен.

Добавлен [тест трёх законов проницаемости на общей форме и CFD-сетке](docs/permeability_models.md): действующий двухчленный, линейный и квадратичный. Подготовка сохраняет происхождение входной формы и хеши сетки; запуск использует один CFD-проход без изменения формы. Пользователь передал результаты серии 8996: при 30° момент отрицателен для всех трёх законов, а его величина существенно зависит от закона. Это проверка чувствительности; сходимость CFD и физическая достоверность оцениваются отдельно.

Для сохранённых фиксированных случаев подготовлен [аудит баланса импульса](docs/momentum_balance.md): давление, вязкая тяга, конвективный перенос через ткань и внешнюю границу, приложенные силы строп. Отдельная утилита читает исходные значения без выполнения условия ткани и без CFD-пересчёта.

Первый аудит 8996 выполнен пользователем на OpenFOAM 2212 и выявил большую невязку момента при точном воспроизведении поверхностных нагрузок. Для её локализации добавлены объёмные операторы давления, конвекции и вязкости, а также разложение отличий от поверхностного баланса. Расширенная проверка требует обновлённых C++-утилиты и Python-обвязки; исходные CFD-поля сохраняются.

Полученный операторный аудит локализовал большую часть остатка в ограничителе градиента давления. Подготовлен [контрольный расчёт с `grad(p) Gauss linear`](docs/pressure_gradient_control.md) на той же форме и сетке. Он изменяет только схему давления и автоматически проверяет это сравнением настроек с исходным `8996/df`.

Репозиторий предназначен для расчёта аэродинамики и формы круглого парашюта при заданном угле атаки. Базовая постановка использует раскройную площадь 6 м², закрытый полюс, проницаемую ткань и стропы, сходящиеся в общем узле. Раскройный диаметр \(D_0 = \sqrt{24/\pi}\) составляет около 2,764 м. Номинальная длина строп равна этому диаметру. За основу масштаба и конфигурации взят эксперимент Носарева. Степень соответствия расчёта эксперименту оценивается отдельно по геометрии, условиям испытания и аэродинамическим коэффициентам.

Связанный расчёт чередует стационарное решение задачи обтекания и структурную релаксацию. OpenFOAM вычисляет поле потока и перепад давления на форме, переданной в начале прохода. Затем нагрузки переносятся на узлы оболочки. Структурная модель обновляет форму, после чего она используется в следующем проходе. Угол атаки задаётся поворотом купола и удерживается, а форма оболочки меняется под нагрузкой. Основные результаты серии — форма, \(C_x\), \(C_y\), \(m_z\) и распределение давления.

## Обновление обработки от 19.11.2026

Пользователь подтвердил запуск непроницаемого купола на кластере. Новые версии обоих Slurm-сценариев автоматически вызывают `nos6_results.py case`: таблицы АДХ, рисунки, два состояния STL, нагрузки на узел строп, эпюры давления, вклад участков в момент, проверку переноса нагрузок и диагностику следа. Итог каждого этапа сохраняется в `out/postprocess_report.json`. GIF включается отдельно через `NOS6_GIF=all`.

Для уже запущенного массива после переноса обновлённых исходников можно поставить обработку в зависимость от его завершения. Здесь J — номер **расчётного** массива, сохранённый при запуске:

```bash
export NOS6_PYTHON=/home/016/apps/dashboard/anaconda3/bin/python
sbatch --dependency=afterany:"$J" cluster/postprocess.slurm "run/nos6wall/$J"
```

Slurm использует отправленную копию сценария, поэтому уже запущенный расчёт сам не перейдёт на новый порядок постобработки. Отдельная задача обрабатывает сохранённые поля без повторного CFD-решения. [Полный аудит, состав результатов, научные источники и ограничения](docs/POSTPROCESSING.md).

## Что изменилось в расчёте

### Остановка связанного расчёта

Серия `nos6_held` по штатному сценарию выполняет от **6 до 12 проходов**. Для ранней остановки структурная релаксация должна завершиться успешно, а невязка формы должна быть строго меньше **`3e-2` от \(D_0\)** два прохода подряд. При включённом сопротивлении строп в те же два прохода дополнительно проверяется абсолютное изменение \(C_x\). Допуск по умолчанию равен `0.003`. Невязка нагрузки между соседними проходами выводится в процентах для диагностики.

Столбец «невязка» соответствует полю `gap` в JSON. Он показывает среднее расстояние между узлами исходной для прохода формы и формы, полученной после структурного расчёта. При заданном угле обе формы приведены к этому углу. Расстояние нормируется на раскройный диаметр и вычисляется до применения коэффициента Эйткена. Например, для купола 6 м² значение `0.03` означает около 8,3 см среднего расхождения. Фактически принятый шаг обновления формы записывается отдельно в поле `shift`. [Правила остановки](coupled/nos6.py) · [Расчёт невязки](coupled/coupled.py)

При достижении предела проходов сохраняется последний завершённый результат. Статус сходимости обозначается файлом `out/nos6_held.done` или `out/nos6_held.НЕСОШЁЛСЯ`. При разборе продолженного расчёта сопоставьте номер прохода в файле статуса с последней строкой JSON. Графики могут быть созданы и для результата, который не удовлетворил критериям. Для сравнения серий фиксируйте статус вместе с АДХ.

### Ткань, стропы и журнал

Штатная серия использует скорость 30 м/с и кинематическую вязкость воздуха `1.46e-5` м²/с. Для модели проницаемой стенки в сценарии заданы `D = 33.2` м/с и `Cw = 28.6`. Сопротивление строп включается при передаче их диаметра в сценарий Slurm. Значение `3.2` мм в примерах служит расчётным параметром. Для привязки к эксперименту его требуется сверить с данными о реальных стропах. Аэродинамический вклад строп записывается в JSON отдельно от общих коэффициентов.

Шапка журнала содержит заданный угол, параметры потока, размеры структурной сетки, данные о стропах, параметры ткани и условия остановки. Для расчёта с преднаполнением выводится заданный \(\Delta C_p\), затем стартовое отношение \(D_p/D_0\). Таблица проходов и диагностические сообщения сохраняются. Запись `V = …` используется при построении графиков, если скорость не передана явно. При заметном расхождении \(D_p/D_0\) в двух состояниях последнего прохода журнал отмечает, что коэффициенты относятся к форме, которую видел решатель. [Сценарий серии](cluster/nos6_held.slurm) · [Чтение параметров для графиков](coupled/plots.py)

## Развёртывание и запуск

Для CFD нужны Linux, Slurm и окружение OpenFOAM с MPI и компилятором для динамического кода. Сценарий по умолчанию загружает модуль `openfoam/2212`. Постобработка использует Python 3.10 или новее с NumPy и Matplotlib. Название модуля на другом кластере можно задать через `NOS6_OPENFOAM_MODULE`. У архива уже выполненного расчёта график формы и таблицу нагрузок можно построить с Python и сохранёнными кадрами. Для повторной трассировки линий тока потребуется OpenFOAM.

Склонируйте репозиторий и подготовьте окружение. Если на кластере уже доступен подходящий Python, установку виртуального окружения можно пропустить и указать его полный путь в `NOS6_PYTHON`.

```bash
git clone https://github.com/ryabkovvd-commits/parachute_openfoam.git
cd parachute_openfoam
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
export NOS6_PYTHON="$PWD/.venv/bin/python"
"$NOS6_PYTHON" -c 'import numpy, matplotlib'
```

Запускайте задачу из корня репозитория. Ниже пример для купола с 24 стропами и угла 35°. Индекс массива умножается на 5. Сохраните номер задания, чтобы затем сразу перейти к результатам нужного угла.

```bash
J=$(sbatch --parsable --array=7 cluster/nos6_held.slurm 3.2 24)
J=${J%%;*}
squeue -j "$J"
W="run/nos6held/$J/a35"
```

Для штатной серии от 0° до 45° выполните `sbatch cluster/nos6_held.slurm 3.2 24`. В сценарии задано до двух одновременно выполняемых элементов массива. Каждый элемент запрашивает один узел и 36 задач Slurm. Раздел, число задач и ограничение по времени проверьте по условиям своего кластера. Если нужен отдельный диапазон, переопределите `--array`. Например, `--array=0-5%2` задаёт 0–25°, а `--array=6-10%2` задаёт 30–50°.

Первый аргумент сценария задаёт диаметр стропы в миллиметрах. Вызов без аргументов оставляет структурные стропы в модели и отключает их сопротивление в потоке. Второй аргумент задаёт число строп. При его изменении сценарий подбирает число узлов по окружности, чтобы точки крепления распределялись равномерно. При исследовании чувствительности к числу строп сравнивайте также фактическую дискретизацию оболочки, указанную в журнале.

## Результаты и постобработка

Каждый угол получает каталог `run/nos6held/<номер массива>/aXX/`. Внутри него используются следующие файлы и папки.

- `out/nos6_held.txt` — постановка, округлённая таблица проходов, предупреждения и причина остановки. Для ошибок OpenFOAM дополнительно проверьте журнал Slurm и `case/log.*`.
- `out/nos6_held.json` — числовая история проходов. Используйте её для сравнения коэффициентов, невязок и длительности. Поле `ratio_seen` описывает форму на входе CFD, а `ratio` — форму после обновления.
- `out/кадры/` — координаты узлов после каждого сохранённого прохода. Финальная обновлённая форма также хранится в `out/nos6_held_shape.npy`.
- `fields/nos6_held/passNN/` — сетка, поля и результаты постобработки OpenFOAM для соответствующего прохода. Карты давления строятся на геометрии этого прохода.
- `pics/` — графики и `parachute.stl`. STL строится по финальной обновлённой форме. При включённом сопротивлении строп в тот же файл добавляется геометрия строп.

### Рисунки

Для перестроения рисунков из сохранённого расчёта при необходимости загрузите модуль OpenFOAM. Переменная `W` указывает на папку одного угла, заданную при запуске.

```bash
module load openfoam/2212
"${NOS6_PYTHON:-python3}" coupled/plots.py nos6_held --run="$W" --V=30 --wake=1
```

При наличии соответствующих данных скрипт строит график сходимости, профиль купола, карту перепада давления, сечения давления и скорости и линии тока. Ключ `--pass=6` выбирает поля шестого прохода. История параметров и график изменения профиля по-прежнему используют сохранённые данные всей серии проходов данного угла. Для продолжения линий через ткань и трассировки течения в следе нужны `simpleFoam`, сохранённая `polyMesh`, поле `U` и поверхностные данные того же прохода, а также словари из папки `case/`. Цвет на рисунке линий тока показывает модуль скорости. Число продолженных линий выводится в терминал и характеризует выполненную постобработку.

### Давление по меридианам и сравнение с Носаревым

Включённый в обновление 19.11.2026 обработчик `coupled/pressure_table.py` использует существующие функции чтения VTP и сглаживания геометрии. Он работает с сохранёнными полями и не запускает OpenFOAM. Перенос этой версии обработчика на кластер пользователем пока не подтверждён. Старый короткий блок из чата был предварительным вариантом выборки.

Для подтверждённого архива при нулевом угле:

```bash
P=/home/016/apps/dashboard/anaconda3/bin/python
"$P" coupled/pressure_table.py run/nos6held/8881/a00 --V=30
```

Выбирается последний проход, для которого одновременно есть запись JSON и пара `master.vtp` / `slave.vtp`. Время внутри `surfacePressure` сравнивается численно. Например, для указанного архива пользователь подтвердил наличие файлов прохода 6 на итерации 2000. Ключ `--pass=5` позволяет выбрать другой сохранённый проход.

В терминал выводится 11 позиций: координата по раскрою, внутреннее и наружное давление, их разность и две координаты профиля. Отрицательная половина координаты относится к наветренному меридиану, положительная — к подветренному. При нулевом угле это условное разделение двух противоположных меридианов. Нормировка давления — `(p/rho − p_inf/rho)/(V²/2)`. Значение `--p-inf` задаётся в кинематических единицах OpenFOAM и по умолчанию равно нулю. Скорость берётся из журнала либо явно задаётся через `--V`.

В `pics/` сохраняются полная и сокращённая CSV-таблицы, JSON с параметрами выборки, `pressure_meridians.png` и `canopy_profiles.png`. Первый рисунок содержит внутреннее и наружное давление и отдельную эпюру перепада. Второй показывает профиль в системе купола относительно среднего центра кромки. Координаты нормированы на раскройный диаметр. По умолчанию предполагается текущий купол 6 м²; для другого масштаба обязательно укажите `--diameter`.

Давление выбирается в секторе ±6° вокруг каждого меридиана с интерполяцией по четырём ближайшим центрам подходящих граней. Нормаль CFD-грани должна соответствовать локальной нормали входной поверхности с отклонением не более 60°. Этот дополнительный геометрический критерий не позволяет малой почти касательной срезанной грани подменять давление на ткани только из-за близости её центра. Порог меняется через `--normal-angle`. Это локальная пространственная выборка, не осреднение по всему кольцу. Для оценки чувствительности предусмотрены `--sector`, `--neighbours` и `--azimuth`. Меридиан 0° проходит через нулевую стропу; например, при 96 узлах и шаге строп 4 направление `--azimuth=7.5` проходит между соседними стропами. Число плотных точек зависит от структурной сетки и `--subdivide`; они не являются независимыми дополнительными CFD-измерениями. Сокращённые строки интерполируются из полной выборки.

Для геометрии прохода N используется входной снимок `input_shape.npy` внутри его архива, если он существует. В текущих архивах такой снимок обычно отсутствует, поэтому берётся кадр после прохода N−1. Форма после релаксации прохода N не подставляется. При отсутствии подходящего кадра обработчик завершается с объяснением; можно явно передать фактическую входную форму через `--shape`. Для первого прохода исходная форма должна быть сохранена отдельно. Профиль строится тем же сглаживанием, что использует экспортёр STL; это входная геометрия конструкции, а не точная линия пересечения полигональных граней snappyHexMesh.

Стороны ткани определяются по нормалям относительно коуша, независимо от имён патчей. Для этой методики требуется не менее 99% площади патча с согласованной ориентацией. Противоположно ориентированные остаточные грани исключаются только из выборки давления; их число фиксируется и выводится. CFD-поля и интегральные силы не меняются. Если площадь неоднозначна, обработчик останавливается. Для глубоко сложенного купола, у которого направление нормали относительно коуша перестаёт определять сторону ткани, нужна другая классификация.

Несколько расчётов можно передать одной команде после определения их путей:

```bash
"$P" coupled/pressure_table.py "$W0" "$W15" "$W40" --V=30 --pics=pics/meridian_compare
```

Фиг. 19а, 20 и 21 Носарева соответствуют круглому куполу при 0°, −15° и −40°. Сопоставляются физически одинаковые наветренный и подветренный меридианы после согласования направлений. Дополнительный ключ `--reference=FILE.csv` накладывает предварительно оцифрованные экспериментальные точки. CSV должен иметь столбцы `alpha_deg,R,p_in,p_out,dp`; строки комментариев начинаются с `#`. На этих графиках интервалы ±0,05 обозначают принятую точность предварительного чтения скана, а не экспериментальную неопределённость. Оцифровку нужно сверить с первоисточником перед количественной оценкой ошибок. Без этого ключа строятся только наши расчётные кривые. Схемы купола над эпюрами Носарева не считаются точными измеренными профилями.

Для открытого полюса предусмотрены `--pole=open --vent-fraction=...`. На рисунках и в таблицах отверстие остаётся разрывом; давление внутри отверстия не выдумывается. При оценке сходимости и момента следует пользоваться исходными интегральными данными; эта локальная выборка не является консервативным переносом нагрузки.

### Контроль непроницаемого купола

`cluster/nos6_wall.slurm` использует те же механику, сопротивление строп и правила остановки, что текущая проницаемая серия. Из команды исключён `--fabric`, поэтому на куполе остаётся штатный `noSlip`. Имя случая **`nos6_held` сохраняется**, а каталог меняется на `run/nos6wall/<номер массива>/aXX/`. Отдельная Python-модель не требуется.

Для продолжения в существующей папке серии задайте перед `sbatch` переменную `NOS6_SERIES_ID`, равную имени папки с уже завершёнными углами. Например, `export NOS6_SERIES_ID=12345` выбирает `run/nos6wall/12345/` для всех новых массивов. Без этой переменной используется номер нового массива Slurm. Перед запуском проверьте `ls -d "run/nos6wall/$NOS6_SERIES_ID/a00" "run/nos6wall/$NOS6_SERIES_ID/a30"`. Указывайте только недостающие углы: `--array=1-5%1` и `--array=7-10%1`. Они используют общую папку серии, но отдельные каталоги `a05`–`a25` и `a35`–`a50`. Повторно запускать один угол в ту же папку одновременно нельзя. Изменение переменной и сценария не меняет уже отправленные задания; после завершения обоих массивов сводные таблицы можно перестроить командой `"$NOS6_PYTHON" coupled/nos6_results.py polar "run/nos6wall/$NOS6_SERIES_ID/summary" "run/nos6wall/$NOS6_SERIES_ID"`.

Для первого контроля при 0° и 30°, по одному работающему углу массива, один узел и 72 MPI-процесса на угол:

```bash
export NOS6_PYTHON=/home/016/apps/dashboard/anaconda3/bin/python
J=$(sbatch --parsable -N 1 -n 72 --array=0,6%1 cluster/nos6_wall.slurm 3.2 24)
J=${J%%;*}
squeue -j "$J"
```

Пользователь подтвердил запуск прежней кластерной копии сценария стенки. В этом обновлении его завершающий блок заменён на единую постобработку; перенос новой версии пока не подтверждён. Создать его из актуальной кластерной копии можно следующими командами из корня проекта:

```bash
cp cluster/nos6_held.slurm cluster/nos6_wall.slurm
sed -i 's/-J nos6held/-J nos6wall/' cluster/nos6_wall.slurm
sed -i 's@run/nos6held/@run/nos6wall/@' cluster/nos6_wall.slurm
sed -i 's/ --fabric=33.2,28.6//' cluster/nos6_wall.slurm
bash -n cluster/nos6_wall.slurm
```

Фиг. 32 Носарева относится к непроницаемому куполу 6 м² с 24 стропами и относительной длиной строп 1. Для определения бокового равновесия после начальных контрольных точек потребуется продолжить углы 40–50°. Прогон остаётся квазистатическим; физические пульсации времени им не воспроизводятся.

### GIF по сохранённым полям

Пример сравнивает первый и двенадцатый проходы архивного расчёта при 35°.

```bash
W=run/nos6held/8883/a35
"${NOS6_PYTHON:-python3}" coupled/plots.py nos6_held --run="$W" --pass=12 \
    --gif=1 --compare-pass=1 --V=30 --wake=0
```

Результат сохраняется в `$W/pics/nos6_held_flow.gif`. Панели используют общий масштаб и цветовую шкалу модуля скорости. Штрихи движутся вдоль сохранённых линий тока. Горизонтальная ось направлена вдоль потока. Кадры анимируют метки в одном поле каждого прохода. Время воспроизведения служит для визуализации.

Чтобы показать все сохранённые проходы одного случая и продолжить линии через ткань, используйте следующий режим.

```bash
module load openfoam/2212
"${NOS6_PYTHON:-python3}" coupled/plots.py nos6_held --run="$W" --gif=all --V=30 --wake=1
```

В `$W/pics/nos6_held_flow_passes.gif` по очереди меняются поле скорости, контур купола и линии тока. Камера, масштаб и цветовая шкала фиксированы для всех проходов. Номер прохода подписан в кадре. Терминал показывает, какие проходы включены и сколько линий удалось продолжить через ткань. Проходы с отсутствующими файлами сечения, поверхности или траекторий пропускаются с сообщением.

Длина стрелок ограничена 12 пикселями по траектории. При переходе к куполу другого размера положение стрелок по линиям тока по-прежнему рассчитывается из поля скорости.

При `--wake=1` статичный рисунок линий тока и GIF используют одну процедуру продолжения траекторий. Для проницаемого купола сохранённая линия, дошедшая до парной грани ткани, соединяется с трассой на выходной стороне. Стрелки движутся вдоль объединённой линии от набегающего потока до следа. Для продолжения нужны `master.vtp`, `slave.vtp`, поле `U`, `polyMesh`, словари `case/` и `simpleFoam -postProcess`. В журнале постобработки отдельно указано число соединённых линий. При `--gif=1` параметры `--compare-run` и `--compare-name` позволяют выбрать другой расчёт для сравнения.

Для проницаемого купола скрипт дополнительно выбирает до 24 пар точек на ткани в плоскости сечения. На входной стороне OpenFOAM трассирует линии назад, на выходной — вперёд. Голубым в GIF выделены только траектории, которые удалось соединить на обеих сторонах. Число точек можно изменить параметром `--fabric-lines=32`. Значение `0` оставляет исходную плотность линий.

Для ускорения обработки всех проходов используйте `--jobs=N`. В задании Slurm запросите одну задачу и `N` процессоров для неё. Скрипт параллельно читает поля и трассирует линии разных проходов. Кадры затем собираются в порядке проходов с общей камерой, а GIF кодируется последовательно. По умолчанию проходы обрабатываются по одному. Для `--wake=1` каждый работник размещает временную копию сетки и полей в каталоге `TMPDIR`. Если Slurm задаёт `SLURM_TMPDIR`, его можно использовать для этих копий.

### Нагрузка на общий узел строп

Эту команду можно выполнить для уже готового расчёта с кадрами, даже если его поля OpenFOAM недоступны.

```bash
"${NOS6_PYTHON:-python3}" coupled/cord_study.py "$W" --loads
```

Скрипт восстанавливает натяжение каждой стропы из её длины и жёсткости, затем суммирует силы строп на общем узле как векторы. В `out/confluence_loads.csv` записываются номер прохода, компоненты силы \(F_x, F_y, F_z\) в осях модели, модуль равнодействующей и максимальное натяжение отдельной стропы. На рисунке `out/confluence_loads.png` показаны модуль равнодействующей и максимальное натяжение по проходам. Все силы даны в ньютонах. Отсутствующие кадры отмечаются предупреждением и разрывом линии на графике. Для записи обоих файлов в другую папку используйте `--output`. [Код вычисления нагрузок](coupled/cord_study.py)

## Дальнейшая работа

После обновления кода проверьте одиночный угол на кластере. В журнале должны появиться допуск `3e-2` и диапазон 6–12 проходов. Сопоставьте итоговый статус, JSON, STL и доступные поля. Затем сравните серии по углам на согласованных геометрии и нормировке. Для \(m_z\) при сопоставлении с экспериментом отдельно фиксируйте точку приведения и направление оси момента.

История нагрузок по проходам описывает переход модели между последовательными состояниями после начального преднаполнения. Чтобы оценить нагрузку во времени и пик рывка при раскрытии, потребуется отдельная нестационарная постановка и проверка по данным раскрытия. Для текущих результатов сравнивайте равнодействующую на общем узле, максимальное натяжение стропы и статус сходимости на одном и том же проходе.

# Поиск сочетания ходов строп при заданном угле атаки

## Запуск на кластере

Для запуска нужен OpenFOAM 2212 и Python 3.10 или новее с NumPy. Из корня проекта:

```bash
sbatch cluster/sector_optimize.slurm --angle 30 --max-cases 60
```

При запуске сценарий проверяет версию Python и импорт NumPy и модуля решателя. Интерпретатор выбирается из `NOS6_PYTHON`. Если переменная не задана, сценарий берёт доступный интерпретатор Anaconda по стандартному пути кластера, затем проверяет системный `python3`. Модуль OpenFOAM можно переопределить через `NOS6_OPENFOAM_MODULE`.

Угол по умолчанию равен 30°. Все случаи одного запуска выполняются при одном угле. Для другого угла запускается отдельный поиск в отдельном каталоге. Флаг `--seed` позволяет указать общий массив начальной формы этой же модели (96 × 12, 24 стропы, закрытый полюс, площадь 6 м²). Решатель выставляет заданный наклон. Если затравки нет, используется штатное симметричное преднаполнение.

Одно задание Slurm запрашивает два узла по 72 ядра. Контроллер ведёт до четырёх независимых случаев. Каждый получает отдельный шаг `srun` на одном узле и 36 процессов MPI внутри проверенной маски CPU. Номер шага, имя узла и список CPU записываются в `cases/<case>/driver.log`. Первый запуск на кластере должен подтвердить фактическое распределение слотов.

Результаты сохраняются в `run/sector_optimize/<job-id>`. Штатный драйвер хранит поля всех проходов. В локальном пилоте один архив прохода занимал около 399 МБ. При 16 проходах на случай и 60 случаях только архивы могут потребовать около 383 ГБ в тех же единицах. Лимит времени Slurm по умолчанию составляет двое суток.

```bash
python3 cluster/sector_optimize.py --work-root run/sector_optimize/preview --angle 30 --slurm-steps --dry-run
```

## Последовательность поиска

1. Рассчитать нейтральную подвеску и четыре управляемые схемы при ходе 2%. Схемы включают три передние, шесть передних, три задние и шесть задних строп. Повторить одногрупповые схемы при 1% и 4%.
2. Для четырёх сочетаний ширины передней и задней групп проверить совместную выборку 2% + 2%. Дополнить её комбинациями лучших ходов из одногрупповых расчётов. Передний и задний приводы могут получать разные команды. Повторные комбинации пропускаются.
3. Для двух наиболее перспективных сочетаний ширины уточнить ход каждого привода в окрестности лучшей проверенной точки. Рассмотреть изменение одного хода и одновременные изменения обоих, включая изменения в противоположных направлениях. Начать с 1 процентного пункта. Когда проверенные соседи перестают улучшать качество, уменьшить шаг до 0,5 процентного пункта. Ходы ограничены 0–4%. Минимальный шаг задаётся через `--stroke-step-bp`.

Входы оптимизации — выбранные стропы и укорочение свободной длины каждой группы. Натяжения рассчитываются конструкционной моделью. Критерий сравнения — `K = |Cy| / Cx` в заданной плоскости, со знаком `Cy` в результатах. Программа проверяет сходимость формы и разброс сил и качества. Моменты записываются для последующего анализа. Нулевой момент не требуется для приёмки точки. Для расчёта свободного движения понадобится отдельная постановка.

Если задано `--max-tension` в ньютонах, проверяется наибольшее натяжение каждой стропы на последних трёх сопряжённых проходах. Итерационный разброс `K` отражает устойчивость численного результата при выбранных настройках. Остальные составляющие погрешности изучаются отдельно.

## Результаты и продолжение

В `summary.json` записываются лучший проверенный набор строп, передний и задний ход в процентах и миллиметрах, угол, качество, прирост относительно нейтральной подвески и натяжения всех 24 строп. Если нейтральная точка не сошлась, сравнение качества команд остаётся доступным, а прирост относительно неё не вычисляется. При достижении бюджета сохраняются рассчитанные комбинации и статус остановки. Результат относится к выбранным группам и углу, заданному для запуска.

Для продолжения укажите прежний рабочий каталог и те же параметры с возможным увеличением бюджета. Используйте тот же исходный код, число MPI-процессов и затравку, если она была задана.

```bash
sbatch cluster/sector_optimize.slurm --angle 30 --max-cases 90 \
  --work-root run/sector_optimize/<previous-job-id>
```
